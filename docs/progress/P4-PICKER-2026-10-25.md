## Pinned picker behavior

The pinned OpenCode 2.0.32 TUI source defines `session.list` as the local
“Switch session” dialog and `open.menu` as the global “Open session or
project” dialog. The global dialog builds session rows from session titles,
with ID and project directory as additional search text, then appends project
rows. Its `DialogSelect` resets a nonempty changed filter to the first
filtered option; Enter submits the currently selected option. Therefore a
single exact global result is sufficient for default selection, while any
second matching result remains unsafe. Sources: [global picker
implementation](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/tui/src/component/dialog-open.tsx)
and [selection state and submit behavior](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/tui/src/ui/dialog-select.tsx).

The private probe mapping now uses `Ctrl-P` for `session.list` and `Ctrl-O`
for `open.menu`. Ordinary A/B, new-root, fork, and Home-return selections use
the local list. Only foreign-project entry and return use the global picker.
The global search uses the unique fixture tokens `Foreign` and `Identity A`.
Before Enter, its fresh managed screen must show exactly two token occurrences
(input plus target row), exactly one full target result, and no other known
fixture result. An extra token occurrence anywhere on the screen, including a
description, fails closed. The existing nonce/sequence observer and refusal
checks remain unchanged.
