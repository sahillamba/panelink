# P5 workspace tab App state — 2026-10-25

## Scope and result

Implemented the route-aware App presentation slice assigned by
`P5-WORKSPACE-TAB-UI-PLAN-2026-10-25.md` and
`P5-TAB-SWITCH-CONTRACT-2026-10-25.md`. The App remains a pure view/input
owner: it receives a validated `WorkspaceIndex` snapshot and typed current
route, and emits a typed destination request. It does not access the store,
filesystem, sockets, servers, or clipboard.

The feature stays disabled for the existing raw/no-tabs App path. With a
workspace catalog installed, row 0 is rendered as the persistent project/tab
strip; the remaining clamped rows form the pane root. Layout requests subtract
one row, pane/divider/modal drawing adds one screen row, and mouse hit, scroll,
menu, and selection coordinates remove that row. Snapshot dimensions remain
pane-content dimensions. Zero and tiny viewports remain bounded.

The project control opens a bounded route chooser. Header tab hits and the
chooser select stable `(ProjectId, WorkspaceTabId)` routes. Ctrl-B `w` opens the
chooser, `n`/`p` navigate tabs, and `[`/`]` navigate nonempty projects through
the pure `workspace_tabs::navigate` model. Choosing the current route closes
the chooser without requesting a switch. No route mutation or pane lifecycle
controls were added.

On selection, the App records one request, cancels selection and queued copy,
drops unsent keys with the existing abandonment path, and immediately freezes
child effects. During preparation it consumes keys, paste, mouse, pane actions,
and modal input without calling child effects. `Ctrl-X` still returns `Flow::Quit`
without flushing while frozen; host resize and local rendering remain usable.
A failed prepare can unfreeze the old App with the fixed
`workspace switch failed` status. The controller must use `route_switching()`
to keep unsafe resize work local while preparing.

## Controller API

```rust
install_workspace_tabs(&mut self, index: WorkspaceIndex, current: WorkspaceRouteId)
update_workspace_catalog(&mut self, index: WorkspaceIndex) -> bool
take_catalog_refresh_request(&mut self) -> bool
take_route_request(&mut self) -> Option<WorkspaceRouteId>
begin_route_switch(&mut self, now: Instant)
finish_route_switch(&mut self, failed: bool, now: Instant)
route_switching(&self) -> bool
```

`install_workspace_tabs` ignores an invalid `(project, tab)` pair and enables
the header only for a valid snapshot route. `take_route_request` is one-shot.
`begin_route_switch` is idempotent for controller coordination and performs
the freeze/cancellation itself when a view selection is made. `finish_route_switch`
clears the freeze; `failed=true` sets the fixed failure status. A successfully
installed destination should use a fresh App and call `install_workspace_tabs`
with its active route.

`update_workspace_catalog` refreshes an already-installed immutable snapshot.
It preserves the active route, freeze, pending typed request, and a still-valid
chooser route. If the chooser's selected route disappeared, it selects the
active route. A snapshot that no longer contains the active route is rejected
without changing the previous catalog. Opening the project chooser sets one
coalesced refresh intent; the host may consume it once through
`take_catalog_refresh_request` and perform metadata IO outside App.

Route entry, chooser opening, same-route selection, and switch completion clear
the Ctrl-B prefix so the next ordinary key is delivered as a child key. Flush
also discards any stale batch while frozen. Recovery-availability probing is
skipped for route preparation, help, picker, and header-row events. Header row
conversion uses checked subtraction, and picker scrolling/rendering/hit tests
share the actual viewport row budget.
