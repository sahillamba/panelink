## Interface and implementation contract

- `TerminalSize` has private rows/columns, checked construction, and getters; accepted range is 5–80 rows and 20–240 columns. A public caller cannot construct an unchecked size.
- `TerminalSession::spawn` receives an already `ResolvedLaunch`, an argument slice of `OsString`, the complete explicit `Environment`, and checked size. Validate absolute executable/cwd and existing executable/directory, argument NULs, environment names/values and exact owned `TERM=panelink-probe` before PTY creation. The caller uses existing launch/environment construction. This internal prototype profile will have a deliberately small checked-in terminfo entry; do not advertise an existing vt100/xterm profile whose character-set or other capabilities the engine/renderer does not implement. Full-screen child testing requires a compiled entry supplied via explicit TERMINFO and later host-renderer checks. The low-level API must still reject forged invalid public inputs. Do not read daemon environment, log arguments/environment, choose another executable or fall back from cwd. Standard `Command::current_dir` must propagate any later cwd failure. Existing filesystem resolution remains subject to TOCTOU; make no executable-identity security claim.
- Create one PTY with rustix-openpty's CLOEXEC descriptors and initial dimensions. Set only its controller nonblocking before spawn. Use `Command` with the absolute executable, argument array, `env_clear` then only the explicit environment, and cwd. Connect cloned slave descriptors to stdin/stdout/stderr. The sole unsafe application block is `pre_exec` registration with a documented safety invariant: its closure only calls the reviewed async-signal-safe `setsid` and controlling-terminal ioctl wrappers, propagating failures; it performs no allocation, logging, locking or environment access. Capture an owned slave descriptor for that hook. Drop the parent Command/slave references immediately after spawn.
- On macOS, openpty sets CLOEXEC after descriptor creation; serialize all core PTY creation/spawns with one process-wide mutex. This protects Panelink's own path, not arbitrary external threads/libraries that spawn independently. Poisoning is a named error. No `login_tty` helper that hides a failed setsid.
- Keep one engine, 1,024 normal history rows (within the experiment's 2,000-row ceiling), and no alternate history. The smaller chosen cap reserves memory for row capacities retained across resize/insert cycles and the visible snapshot; it is a prototype budget, not a product retention decision. Do not clone an engine screen/history to render. Feed at most 16 KiB per read/processing step. Do not accumulate a PTY-output log. Unsupported titles, hyperlinks, shell integration and resize requests from child output have no host effects.
- `pump` makes bounded progress: at most one 16 KiB nonblocking read, engine processing/callback handling, a bounded input-write attempt, a pending absolute resize if any, and `Child::try_wait`. No blocking read, `read_to_end`, unbounded drain loop or wait. EOF drains bytes already read and preserves final screen state. A hard read/write error closes the session through the same bounded cleanup path. `WouldBlock` preserves only this live PTY's bounded pending input; Interrupted can defer to the next pump.
- Typed `Key` input supports printable Unicode characters, Enter, Tab, Backspace, Escape, Interrupt, arrows, Home and End. Reject control scalars in the printable-character variant. Encode cursor keys according to engine application-cursor mode. No API forwards a raw host input escape stream. Explicit `paste(&str)` is a separate caller-authorized operation; bracketed framing follows engine mode.
- The complete encoded input queue is at most 65,536 bytes. Check the entire encoded paste, including framing, before allocating/adding it, or return a named queue-full error without sending a prefix. Partial writes remove exactly the accepted prefix. On hard error report only accepted-byte count if needed, discard the remaining suffix and permanently disable further input; never resend after failure, exit, shutdown or another session. Child exit discards unsent input. No Debug output may expose arguments, environment, input/paste, pending bytes, child control strings or screen text.
- Query callbacks see classified engine CSI parameters, never a second parser. Accept exactly the four query classes in P2-EXPERIMENT: primary DA (`CSI c`/default-zero parameter), status (`CSI 5n`), cursor (`CSI 6n`), and size (`CSI 18t`). Require no intermediates, no unexpected parameter/subparameter fields. Responses are exactly `ESC[?1c`, `ESC[0n`, `ESC[row;colR`, `ESC[8;rows;colst`. Cursor is one-based and clamped to the visible dimensions at the wrap boundary. Replies go to the same child PTY; never stdout/stderr or host APIs. Drop all other queries. Bound replies to 64 per monotonic one-second window, 256 bytes each and 64 pending events; no unbounded event/string queue. Backpressure may drop replies, never expand queues. Ignore child-requested host resize.
- Clipboard write/clear callbacks do nothing and retain no payload. OSC52 reads are ignored without queuing any response to child input; an empty response can be interpreted as shell input. Drop unsupported selectors and other/malformed requests; no host clipboard calls, subprocesses, prompts, delayed actions or raw OSC forwarding. Report parser truncation behavior accurately; do not claim discarded oversized controls were fully validated.
- `request_resize` coalesces to one newest checked size. Commit engine dimensions only after `tcsetwinsize` succeeds. Failure leaves previous accepted dimensions intact. A focused helper with an injected failing resize operation may test this transaction without invalidating owned descriptors.
- Provide a single retained screen snapshot accessible by reference; rebuilding it cannot retain old snapshots inside the core. It contains only visible cells, cursor/mode/dimension fields and needed color/style attributes. Sanitize C0, C1, DEL, ESC, bidi controls and Unicode line/paragraph separators to U+FFFD before exposing snapshot text to a future renderer; preserve ordinary scalars and the engine's width/continuation information. Bound each cell's storage from the reviewed fixed upstream cell representation. Never expose an upstream `contents_formatted` byte stream as host output. Snapshot construction must not clone history. The parent records a conservative engine + snapshot allocation bound separately.
- Explicit shutdown closes the controller on success or error and forbids further pump/resize IO; key/paste remain disabled. Natural child exit permits final output draining until EOF. `shutdown` sends HUP to the still-owned child process/group, polls `try_wait` for up to one second, sends KILL if still live and polls/reaps for up to one more second. It reports a timeout and returns rather than waiting indefinitely. Cache cleanup attempt/result so explicit cleanup plus Drop cannot repeat a two-second timeout. `Drop` uses this same bounded cleanup and closes descriptors; it never writes input or calls blocking wait. Do not signal a reused PID after the child has already been reaped. Do not claim control of descendants that escape the managed group/session. All failure paths after spawn preserve these rules.

Use named errors with stable operation labels and `io::ErrorKind`, not stringified OS errors that may contain caller-controlled data. Public docs must distinguish this disposable same-process core from future server lifetime and recovery.

## Meaningful verification

Use deterministic harmless fixtures, with a deadline for every test I/O loop and cleanup on failure. Tests may run `/bin/sh`, `/usr/bin/env` and `/bin/stty` with explicit synthetic contexts. No test mutates the process-wide environment, touches the system clipboard, or reads secrets.

- Real PTY isatty on all child stdio descriptors, explicit cwd and environment, no inherited parent-only variable and no implicit SHELL; nonexistent cwd/executable/invalid environment/invalid dimensions rejected.
- Child output updates engine/snapshot; EOF and exit status collected. Normal and alternate screens stay separate; repeated output respects history cap. Large OSC and combining floods exercise the reviewed preallocation bounds; oversized CSI insertion does not inflate retained state.
- Exact bytes for all four allowlisted query responses through engine callbacks and a real child PTY. Unsupported/malformed queries produce no reply; clipboard writes/clears have no effect and reads never queue reply bytes. No host side effects or retained clipboard payload.
- Queue boundary and atomic bracketed paste rejection; partial writer, WouldBlock, hard error, exit with pending input, and no input after cleanup. Use a focused writer abstraction to inject partial/error behavior where OS scheduling cannot reproduce it deterministically.
- Resize/coalescing updates actual child PTY size and snapshot; injected resize failure preserves previous dimensions.
- Snapshot canaries for ESC, C0/C1, DEL, bidi controls, separators, ordinary Unicode, combining and wide-continuation cells; no raw child controls reach a host-output path (there is no host renderer in this task).
- Normal cleanup and HUP-ignoring child both reap within the stated bounded windows or report timeout without hanging. No writer-drop input injection.
- Debug/error redaction tests with harmless markers, never real credentials.

No pass claims for unrun/manual tests. Parent independently rechecks selected claims and full integration.
