Implement a v1.0 big-endian envelope. Exactly 24 header bytes: offsets0..4 u32 frame length (remaining bytes, excludes its own4 bytes),4..8 literal PLNK,8..10 u16 major1,10..12 u16 minor0,12..14 u16 message kind,14..16 u16 flags0,16..24 u64 request ID. Declared frame length is20+payload length. Known kinds numeric1 Hello,2 Welcome,3 Request,4 Response,5 Snapshot,6 Error. Hello/Welcome/Error payload cap4096; Request/Response cap65536; Snapshot cap2097152. No compression, reserved flags or other version accepted. request ID0 is allowed for future unsolicited events; this task does not assign authority to IDs or interpret opaque payloads.

Public constants HEADER_BYTES=24 and protocol major/minor; MessageKind enum. FrameHeader has validated kind, request_id and payload_len with getters. decode_header(&[u8;24])->Result<FrameHeader,WireError> validates magic/version/kind/flags/length and per-kind cap without allocating. Frame<'a> borrows the payload; constructor validates cap, accessors expose header/payload. decode_frame(&[u8])->Result<Frame<'_>,WireError> requires exactly one complete frame, rejects truncation and trailing bytes and borrows input rather than allocating. encode_frame<W:Write>(&Frame<'_>,&mut W)->io::Result<()> validates before first write, writes one header and payload, propagates first error without retrying an entire frame. Constructor error is WireError; writer validation error maps InvalidInput. No owned frame payloads or unbounded reader API. Custom Debug for Frame exposes only numeric header metadata, never payload contents; WireError is fixed variants with no input data. MessageKind/Header safe derives allowed. All production types/functions documented. No whole-message serialization or schema claims.

Meaningful tests: exact golden bytes independent of encoder; roundtrip all6 kinds and binary payload; partial headers and bodies, length<20, mismatched/trailing bytes, bad magic, major/minor, unknown kind, nonzero flags; exact per-kind payload boundaries and one over; u32::MAX rejected in decode_header without allocation; returned payload points into source; failed encode writes only accepted prefix and never restarts; diagnostics/Debug omit payload canary. Exact lengths must use checked arithmetic; no unsafe code. Proposed scenarios become evidence only when run.
